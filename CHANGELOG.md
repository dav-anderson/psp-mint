# Changelog

psp-mint 0.1.2 builds on `sp-wire` 0.2.0 (wire version 2, AIR 2.0.3) and mint-core 0.1.3. Nothing was recorded per version before this file; the section below is everything the README said about what was built and when.

## 0.5.0 (unreleased): the SPI gaps (ROADMAP item 20, items 8, 14 and 10)

- **Changed: a spend's `pay` is reissued, not burned (behaviour change).** With the new settings `burn.enabled` (default `false`) and `burn.threshold_psp` (default `0`) the mint reissues every paid unit as PSP notes written to `revenue/<request hash>.json` for the SPI's ecash-wallet (`ecash-wallet receive-psp`), or, with burning on, only while the SPI's wallet holds less than the threshold, and burns the rest. The figure compared is the SPI wallet's current PSP balance, as `spi` last published it in `wallet_balance.json` (`burn.balance_file`, `burn.balance_max_age_secs`) plus what the mint has reissued since; a missing, malformed or stale figure reissues everything (`src/balance.rs`). `/audit` has `burned` and `reissued` beside `paid`. A spend's notes are redeemed whole, so after a spend with burning off `outstanding` no longer falls by `pay`. New fields in `rollovers.json` (`paid_burned`, `paid_kept`, `plans`, `revenue`), no migration: pre-release.
- **Added: `SIGHUP` reloads the settings** (`config::Handle`), as esp-mint does. Before, `SIGHUP` ended the process. Every setting is marked "reloads live" or "needs a restart" in `config::SPECS` and in the README ("Reloading, restarting and snapshots", and a column of the Settings table); fees and limits reload live. A reload names a changed restart-only setting and leaves its running value; nothing restarts the mint. `scan.health_intervals` and `scan.health_grace_secs` reload live (`Health` keeps the limit in an atomic).
- **Added: the snapshot (`SIGUSR1`).** `serve` stops the scan, the AIR listener and the local API in order, drops every store, copies the data folder to `snapshots/<UTC time>/` and opens the data again; sled writes everything when its last handle drops, so no flush in mint-core is needed. `serve` is an outer loop (`main.rs`); `src/snapshot.rs` and `src/stop.rs` are new, and `/health` has `version`. If a task still holds a store when the local API has stopped, a snapshot is refused and the process exits with status 1 so that the service manager starts it again. Upgrades and changes to restart-only settings are a brief downtime (stop the old process, start the new one); the no-downtime upgrade that was built for them in an earlier draft is removed and deferred to ROADMAP item 25.
- **Fixed: every stop panicked.** `serve` built `tokio::time::timeout` outside the runtime when it waited for the local API to drain, which panics with "there is no reactor running"; SIGTERM, every restart and the snapshot all hit it. The timeout is now made inside `runtime.block_on(async { .. })`. `tests/serve_process.rs` runs the real binary, sends SIGTERM and checks exit status 0 and the line `psp-mint: stopped, the data is closed`.
- **Changed: `burn.balance_max_age_secs` defaults to 86400 (24 hours; it was 3600).** The figure only has to be close: `spi` refreshes it on `collect` and `audit` and runs no timer. Older than the limit, the mint reissues every paid unit and burns nothing. A spend made with `ecash-wallet` directly is not seen until the next `collect` or `audit` (README, DESIGN "Reissuing the payment"). Still an operator setting.
- **Added: `--version` / `-V`**: the program's version and the sp-wire, mint-core and air versions in `Cargo.lock` (`build.rs`, `src/lockfile.rs`).
- **Tests.** Changed expectations, all for the reissue default: the `totals` of `tests/spend.rs` (issued and outstanding now include the reissued PSP) and the crash test, which now carries the saved plan. Added: reload (live, restart-only, bad file, the health allowance), the burn settings, the threshold split, burn with a zero threshold, `--version`, the lockfile reader, the README reload lists, the SIGTERM test on the real binary. The tests of that earlier draft are removed. None has been run (no cargo where this was written).

## 0.5.0 (unreleased): regtest round 1 (ROADMAP item 18)

- **Behaviour change: caps on the size ceilings and the item count, checked when the settings load.** `server.melt_max_request_bytes`, `server.rollover_max_request_bytes`, `server.burns_max_request_bytes` and `server.check_state_max_request_bytes` are 16,384 to 15,728,640 bytes (were 4,096 to 1 GiB; 15 MiB is the most one AIR message carries). `rollover.max_items` is 64 to 25,000 (was 1 to 100,000). The three flat fees (`reconciliation.fee`, `reconciliation.write_fee`, `delivery.read_fee`) get no cap: they keep their old bound of 0 to 2^62 and are 0 by default. PSP units cannot be split and nothing stops a buyer from making a small purchase anyway, so raising these fees can eat up a small purchase before delivery; `settle.rs` holds a purchase that `delivery.read_fee` eats up as `paid_unsettled` (a `Held` delivery, 0 units due), and a credit that `reconciliation.fee` eats up comes to 0 units due; a reconciliation of either is refused with `nothing_to_issue` and the payment or credit is forfeited when its window closes (DESIGN.md says so). Defaults are unchanged. A settings file outside a range now stops the mint at start, naming the setting, the value and the range. The numbers are worked in DESIGN.md, "Caps on sizes and fees".
- Credit rounding: no change. The PSP already keeps the sub-cent fraction of a credit, and the cents remainder under `reconciliation.round_up_from`; the rule is now written down in DESIGN.md ("Rounding: who keeps the fraction").
- Tests: 5 added in `config.rs`, one for each cap on a size ceiling or the item count (melt, burns, rollover, check-state and `rollover.max_items`).

## 0.5.0 (unreleased): signatures delivered over AIR

**PSP reconciliation over AIR (unreleased).** Needs the `KIND_PSP_RECONCILE` (15), `ReconcileRequest`, `ReconcileResponse` and `ReconcileRules` of the matching sp-wire (and the `rules` field of the delivery bodies).

- **New: the reconciliation (AIR kind 15).** One kind for the corrected request (a held or rejected payment) and the credit claim; the stored rules tell them apart. The request is signed by the purchase's reply key (BIP340, over its digest), is checked against the rules fixed when the window opened, and is signed whole or not at all at exactly `due_units`. An accepted request is answered; anything else gets **no reply** (`Served::Ignored`), with the reason only in the log. Requests refused for their content are counted per payment up to `reconciliation.max_attempts`; a bad signature, an unknown, ambiguous or closed payment, a resend of a refused request and a mint failure are not counted. See README "Reconciling a payment (kind 15)" and DESIGN "Reconciliation over AIR (kind 15)".
- **New: the rules up front.** The first delivery (kind 13 `Signed` with a credit, `Refused`, `Held`) carries `rules`, and the record stores the same ones. Changing a setting later changes no payment already open.
- **New: crash safety as the rollover's.** The accepted request is saved as `reconcile_pending` before anything is signed; the close (the answer by request hash, `settled_at`, the pending entry cleared) is one write; an identical resend finishes an interrupted request (an output already signed is signed again, counted once); `forfeit_expired` skips a payment with a pending reconciliation.
- **New: five settings, all defaulting to 0 fees:** `reconciliation.fee`, `reconciliation.max_attempts` (2), `reconciliation.write_fee`, `reconciliation.round_up_from` (9, in cents, 1 to 10) and `delivery.read_fee`. The prepaid AIR read and write are amounts only for now.
- **New: one payload, one payment.** A second payment carrying a payload already used is rejected as `DuplicatePayment`, kept with `duplicate_of`, with no delivery and no window, and audited apart.
- **New: `/audit`'s `reconciliation` section** gains `settled`, `duplicates`, `fees_units`, `read_prepaid_units`, `write_prepaid_units`, `rounding_kept_cents`, `rounding_given_cents` and `refused_attempts`.
- **Changed: the records are shared** between the scan thread and the AIR listener (`SharedRecords`, lock order records, mint, rotor; the scan never holds them across the wallet scan, a price fetch or a delivery write). `Record` gained `rules`, `read_prepaid_units`, `kept_cents`, `given_cents`, `duplicate_of`, `attempts`, `refusals`, `reconcile_pending`, `reconciled`, `settled_at` and `credit_claimed_cents` (all optional, skipped when empty, so old files read and plain records are written as before). `Reconciliation` gained the fields above. The old `pass` and `run_once_rotating` are kept; `run_once_shared`, `Deliverer::pass_shared` and `server::air_served_with` are the shared forms.
- Tests: `tests/reconcile.rs` (direct, through the listener's entry, and over a real `air_server`), settle tests for the rules, the rounding, the read fee and duplicates, records tests for the new fields, and config tests for the settings.
- Docs: README (kind 15, the five settings, `/audit`), DESIGN ("Reconciliation over AIR (kind 15)", record columns, the placeholders replaced).

**A PSP spend with change over AIR (unreleased).** Needs the `KIND_PSP_SPEND` (14) and `PspSpendRequest` of the matching sp-wire.

- **New: the spend (AIR kind 14).** Notes in, change out, an amount `pay` that is burned and never reissued, and a memo; the inputs must be worth the change plus `pay` exactly. Modelled on fsp-mint's spend, with the rollover's keysets (each input names its keyset; the change is signed by the current or the previous one) and the rollover's crash safety: the request is saved as pending with its notes before any burn, the burn is recorded, the change is signed (an output already claimed is signed again), and the answer is stored with `pay` added to the paid total in one write, only then is the reply made. A retry gets the stored answer and burns nothing more. Checks, cheapest first, with their codes: `no_inputs`, `too_many_items`, `memo_too_long`, `missing_keyset`, `nothing_to_pay` (a `pay` of 0 is a plain rollover), `not_exact` (summed in `u128`), `duplicate_input`, `duplicate_blind_nonce`, `bad_denomination`, `keyset_retired`, `unknown_keyset`, `bad_note`, `bad_spend_signature`, `note_spent_elsewhere` (with `spent`) and `note_held`.
- **New: `/audit` has `paid`,** the PSP units burned as payments by spends, apart from what the ESP mint burns through `/melt` for exchanges. It is part of `redeemed`. It is kept in `rollovers.json` (new fields `spends` and `paid`, both defaulted, so old files read), saved in the same write as the answer it counts.
- The spend shares the rollover's ceilings (`server.rollover_max_request_bytes`, `rollover.max_items`); no new setting. The memo is not recorded with the burn, so a payer's memo cannot pass for an exchange's in `/burns`. Rollover, `/melt` and purchases are unchanged. Fees stay 0.
- Tests: `tests/spend.rs`, over AIR: a spend with change (and its retry); an exact spend with no change; inputs not equal to change + pay (including a `pay` that would wrap a `u64`); `pay` 0; a spent note, which is named; the same note in two spends; the previous, a retired and an unknown keyset, for the notes and for the change; the payment counted apart from an exchange's melt; a crash after the burn and a crash while signing, each finished by the retry with the payment counted once, and the held note refused to anyone else meanwhile; the shape checks and the ceilings; and a `rollovers.json` from before spends.
- Docs: README (the new kind, the audit field, the settings it shares), DESIGN ("The spend").

Builds on `sp-wire` 0.5.0 (`air_request::delivery`).

A held or rejected purchase is delivered too, and every unsettled payment now has a reconciliation window (below, the last four items).

- **New: each purchase's signatures, or its rejection, are written as one write-once AIR record** on `air.server`/`air.host`, signed by the mint's DID key and sealed to the payload's reply DID, at an address derived from the mint's DID, the reply DID and the purchase (`sha256("sp-psp-purchase-v0" || opened payload)`). It carries the signed pairs and the current and previous keysets (so the wallet makes no keys call), the units not signed and the credit owed, or, for a payment that signed nothing, that it is held or was rejected, with the reason and what was paid. An issued purchase, a held payment and a rejection after a readable payload get a record; an unreadable payload does not (the payer takes the loss). A rejection delivers the reason and does not refund the bitcoin.
- **New: `delivery::Deliverer`, run after every scan** (`run` once, `serve` every cycle, even when the scan failed). Retries every record not yet stored with a wait that doubles from 10 seconds to 15 minutes, across restarts; the sealed bytes are saved in the settlement record before the first write, so every retry writes the same bytes. A write to a taken cell is answered as a read: the same bytes count as delivered, different bytes are reported and never overwritten, and a reply DID that is not a key is abandoned with the reason. Delivery never blocks or undoes issuance, and adds no required setting (it uses `air.server`, `air.host` and `air.timeout_secs`, which now also bounds a connection).
- **New: `Record.delivery`** (`records::Delivery`) holds the outcome, the sealed record and whether it is `delivered` or `abandoned`; `Records::undelivered` and `put_delivery`. Settlement files from before this change read as they were (the field defaults to none).
- **Behaviour change: `describe` is a log only.** The payer gets the signed pairs over AIR, and the record is the only copy of them (the scan log prints counts and units, not signatures: see the first item of this release's test-suite audit above).
- **A crash after a payment is marked issued and before its signatures are stored** still loses them, as before. They are stored by the second `records.put` in `settle`, right after `issuer.issue`. The signatures are kept nowhere else, so the loss is accepted. It cannot be closed without signing again, which needs mint-core (its logic refuses a blind nonce it has used). A held or rejected payment signs nothing and has one write.
- **New: the reconciliation window.** `settle.reconciliation_window_days` (`PSP_RECONCILIATION_WINDOW_DAYS`, 14, 1 to 365) is how long a credit, a held payment and a rejected purchase with a readable reply DID stay open. It goes into `settle::Terms.reconciliation_window_secs` and is stamped on the record as `open_until` and in the record the payer is sent. The wallet learns it from there and needs no setting. The default is 14 days (decided 2026-10-21); the range stays 1 to 365.
- **New: forfeiture.** `Records::forfeit_expired(now)` (run after every scan, in `run` and `serve`) sets `forfeited_at` on a payment whose `open_until` has passed and that is still open; the mint keeps the bitcoin and the payment is no longer owed. Prints `forfeited <txid>`. Whatever later settles a payment must clear `open_until`.
- **New: `/audit` shows the open and forfeited payments apart** in a `reconciliation` section (`open` and `forfeited`, each with `payments`, `sats` and `credit_cents`), added by `server::router_audited` around mint-core's audit body, which is unchanged. `router_full` is `router_audited` without the settlement file.
- **Changed: `paid_unsettled` now delivers a `Held` record** (it had none), and a rejection's record carries `paid_sats`, `paid_cents` and `open_until`. `Record` gained `open_until` and `forfeited_at`; older files read as before (both absent).
- Tests: `tests/delivery.rs` against a real `air_server` (settled and delivered, a rejection with what was paid and its window, a held payment delivered and forfeited when its window closes, an unreadable payment has none, the AIR server down then a restart delivering exactly one record, an unacknowledged write found stored, a different record never overwritten, a non-key reply DID abandoned, an old settlements file); unit tests of the stored delivery in `settle` and `records`, and of the backoff schedule.
- Tests: `tests/reconciliation.rs` (`/audit` shows open and forfeited apart, with and without rotation, and has no section without the settlement file); unit tests for the window in `settle`, `records` and `config`.
- Docs: README (delivering a purchase, the reconciliation window, `/audit`, the commands, `air.timeout_secs`, the new setting, tests), DESIGN (signature delivery, the reconciliation window, settlement records, the wallet).

## 0.5.0 (unreleased): HTTP gone where AIR has replaced it

Wallets reach this mint over AIR and only over AIR. The HTTP routes that AIR replaced are removed, with the code only they used; what is left on HTTP is local to the SPI and the operator.

**Behaviour change.**

- **HTTP is gone for the wallet's calls.** `GET /keys`, `GET /keysets`, `GET /rotation`, `POST /rollover` and `POST /check-state` are no longer routes (in either router); a request for one is a `404`. They are answered by the AIR listener (kinds 2 to 6), with the same bodies and the same ceilings. `/melt`, `/burns`, `/audit` and `/health` stay on HTTP: the SPI uses them.
- **AIR is required.** `serve` stops at start if `air.server` (`PSP_AIR_SERVER`) or `air.host` (`PSP_AIR_HOST`) is missing, with a message that names the setting. Other commands do not need them.
- **`air.enabled` (`PSP_AIR_ENABLED`) is gone.** The listener always runs. A file or an environment that still sets it stops the mint when the settings load, with a message that says to delete it (a setting that does nothing, silently, would look like a choice).
- **`server.bind` (`PSP_BIND`) must be a loopback address.** The settings refuse any other IP when they load (any command). The default `127.0.0.1:3000` is unchanged.
- **A listener that fails ends the process** (exit status 1, message on stderr), so that a supervisor restarts it and it resumes from its counter. It used to log and leave the HTTP server running, which is now a mint nobody can reach.

**Removed.** The handlers and routes above, the unrotating router's `/keys`, `/check-state` and the rotation routes, and the code only they used. `server::router` (without rotation) serves `/audit`, `/melt`, `/burns` and `/health`; `router_full` with rotation serves the same four. `main.rs` always builds the rotating mint. The functions that build the wallet calls' answers (`keys_response`, `keysets_response`, `rotation_response`, `rollover_response`, `check_state_response`) are kept: `air_served` calls them.

**Tests.** The tests of the removed routes call the AIR listener instead, on a real `air_server` in the test process (new `tests/common`): `rotation_http.rs` (rotation, keysets, rollover and check-state), `api.rs` (keys and check-state, and a test that the five routes are `404` on HTTP), `limits_http.rs` (the check-state ceiling at 4097 and 4096 bytes over AIR; the 3 MiB ceiling test now runs on `/burns`). `/melt`, `/burns`, `/audit` and `/health` stay HTTP, as `network_http.rs`. `air_info.rs` no longer compares AIR replies with HTTP routes, which are gone. A refusal over AIR is read as `400`; a ceiling is told apart by `code` (`request_too_large`).

## 0.4.0, AIR rollover and check-state (unreleased)

- **The AIR listener also answers a wallet's `POST /rollover` and `POST /check-state`** (request kinds 5 and 6 of `sp_wire::air_request`), the first calls with a body and the first that change the mint's state. The body is the request JSON the route takes; the reply body is the JSON the route returns, built by the same functions (`rollover_response`, `check_state_response`, which the handlers were split into without changing what they do), so the two cannot differ.
- **The same ceilings over AIR as over HTTP:** `server.rollover_bytes` and `server.check_state_bytes` (over the body, before it is parsed) and `server.rollover_notes`. Over a ceiling is a signed refusal with the `413` JSON (`request_too_large`, `size_bytes`, `limit_bytes`); a body that is not a request is a signed refusal `malformed_request`.
- **A refusal is a signed reply with status `refused` (2) and the HTTP `400` body** (`refused`, a keyset code, `note_spent_elsewhere` with `spent`, and so on); a `5xx` is the existing signed `unavailable`. `server::air_served` takes the limits and the body, and the listener's `Serve` is `Fn(u8, &[u8]) -> Option<Served>`.
- **A resent request gets the same reply, not a second rollover.** Nothing new was needed: `rotation::rollover` answers a body it has answered from its store (keyed by the request hash, written before any note is spent), so a second delivery in another slot, a mint that crashed after answering, and a wallet that starts over with a new request id all end with the stored answer; the write-once reply cell keeps the first reply.
- Tests in `tests/air_info.rs`: both calls compared byte for byte with the HTTP routes, a resent and a copied request, the refusals (cap, unknown keyset, spent note, over the ceiling at 4097 and at 4096, not JSON), a poisoned lock, tampered and wrong-kind replies for a rollover, and a **full 1000-note rollover** and a 1000-nonce check-state over AIR.

## 0.4.0, AIR listener (unreleased)

- **The AIR listener also answers keys, keysets and rotation.** A wallet's `GET /keys`, `/keysets` and `/rotation` can be asked over AIR (request kinds 2, 3 and 4 of `sp_wire::air_request`); the reply body is the exact JSON the HTTP route returns, built by the same code, and is signed with the mint's DID key, so nothing between the wallet and the mint can substitute keys. A call the mint cannot answer now (the mint lock is poisoned, a rotation step failed) gets a signed reply with status `unavailable`, so the wallet fails at once. The HTTP routes are unchanged (their handlers were split into a function that builds the response and a thin handler). No new setting. Tests in `tests/air_info.rs`: each kind compared byte for byte with the HTTP route against a real rotating mint, a poisoned mint answering `unavailable` (and still answering mint info), tampered, forged, replayed and wrong-kind keys replies rejected.
- **An AIR listener answers a wallet's mint-info request, beside the HTTP server. Off unless `air.enabled` is true.** The first call between a wallet and this mint that does not go over HTTP: what `GET /health` reports (`status`, `wire_version`, `network`), signed with the mint's DID key (`mint_did_key.json`). The listener holds 16 reads on mailbox slots of the mint's DID, opens each request, answers it, and creates the reply in the write-once reply cell (first write wins, so a retry gets one reply). Junk in a slot is skipped. The counter `next` is the file `air_mailbox_next` in the network's data folder, beside the rest of the local state and not under the storage policy; it is rebuilt by probing from slot 0. If the AIR client gives up, the listener logs it and ends; HTTP keeps running. New module `air_listener`; `Health::mint_info`; `serve` starts the thread. The wire is `sp_wire::air_request` (sp-wire's new `air-request` and `air-client` features); no `WIRE_VERSION` bump.

## 0.2.0

- **`POST /rollover` signs the outputs with the live key set the request names, current or previous.** Before, a request naming the previous set was refused `400 keyset_not_current`. Now only a set that is not live is refused: `keyset_retired` for a deleted one, `unknown_keyset` for anything else, before anything is burned. A request resumed after a crash is signed by the named set while that is live, and by the current set once it has been deleted. `keyset_not_current` is no longer sent; `sp-wire` keeps the name reserved.
- Tests: the rotation test now rolls over with outputs naming the previous set (signed by it, the answer names it), a retired set (`keyset_retired`) and an unknown one (`unknown_keyset`).
- **Settings for the `/rollover` limits.** `server.rollover_max_request_bytes` (`PSP_ROLLOVER_MAX_BYTES`, default 1 MiB) is the ceiling on a `POST /rollover` body; it used to borrow `server.melt_max_request_bytes`. `rollover.max_items` (`PSP_ROLLOVER_MAX_ITEMS`, default 1000, the old constant `MAX_ROLLOVER_NOTES`) is the most notes in one rollover. Tests: the settings' defaults, ranges and environment overrides; a rollover body over the ceiling gets `413`; a rollover over the note cap gets `400` and burns nothing.
- **A BTC claim is signed with the live key set its payload names.** The wallet now names the set it last saw in a purchase (before, it sent none). The mint signs with that set while it is live (current or previous), else with the current set. The printed `keyset <id>` line still says which signed. No byte of the wire format changes. A note signed by the previous set expires sooner, at the next rotation. Tests: a payload naming the previous set is signed by it; one naming no set, or a deleted one, by the current set.

### Migrating old data

**Migrating old data.** Before this change the data sat directly in `~/.psp-mint` and was regtest data. The mint refuses to run (every command except `config`) while those files are there, and tells you to run `cargo run -- migrate`, which moves them into `~/.psp-mint/regtest`. It only renames, and it refuses if the target already holds a file of the same name. The regtest wallet name default changed from `psp` to `psp-regtest`: set `PSP_WALLET=psp` (or `bitcoin.wallet = "psp"`) to keep an old wallet, or create `psp-regtest`.

### The scan

`scan.max_transactions` (`PSP_SCAN_MAX_TRANSACTIONS`) is retired: the scan has no window any more, and setting it stops the mint with an error saying so.

### Wire version

, so the paths did not change

(2: version 1 was the first release, with AIR 1.1.0's sealed envelope; version 2 is AIR 2.0.3's, 80 bytes of overhead instead of 82 or 83, and the only change)

### Settlement rules

The top denomination is 2^24 so that a purchase still covers the same dollar range (it was 2^20 at one PSP to the dollar).

### Encryption

Version 1 (AIR 1.1.0) used a `postcard` envelope of 82 or 83 bytes, and the mint no longer reads it (see "Wire format and versions").

At one PSP to the dollar a purchase under $10,000 took at most 13 notes (648 bytes); at ten to the dollar it takes at most 16 (771 bytes), the cost of the finer unit.
